# Design POV — Shelf drawer: bounded, self-scrolling panel

**Task:** `agent-kanban-shelf-bookkeeping-drawer-body-unbounded-no-internal-scroll`
**Seat:** frontend-design POV (design brief leg of the UI-task gate). Intent + rationale only — NOT code.
**Bug (pre-root-caused):** `.ak-shelf[open] > .ak-shelf__body` (globals.css:590-596) is `display:flex; flex-direction:column` with gap+padding but **no max-height, no overflow-y** → all 133 bookkeeping + 20 parked cards render as one unscrollable inline wall. The document root scrolls; the drawer itself does not.
**cairn:** "A drawer without max-height+overflow is not a scrollable panel, it's an ever-growing column … .ak-shelf__body had neither, so 133 cards rendered as an unscrollable wall (fine at 5, broke at 133)" (T1 2026-09-11, `6bae4820…jsonl:426`). The board already has the *right* pattern in `.ak-drawer__body` (globals.css:1467-1474) — mirror its scroll mechanics, not its flex wiring.

## 1. How tall — viewport-relative, visual-viewport unit
The opened body becomes its **own bounded scroll region** with a `max-height` expressed in **`dvh`** (dynamic viewport height) — never a fixed px cap, never `vh`. Intent: **roughly half to two-thirds of the visual viewport** — tall enough to show a handful of cards at once (so scrolling reads as paging a list), short enough that the board strip above and the page's bottom edge stay as spatial anchors so the drawer never *feels* like the whole screen. The click-through `.ak-drawer` uses `86dvh` because it is a fixed full-takeover overlay; the shelf sits INLINE in document flow, so it must claim LESS — it is a panel among others, not a takeover. `dvh` (not `vh`) is load-bearing: on mobile the URL bar show/hide changes the visual viewport; `vh` locks to the *large* viewport and would clip the last card / break overscroll when the bar is showing.

## 2. Scroll affordance — bold, on-aesthetic "this scrolls" signal
Two cues, chosen for THIS dark-console look (mono, faint lines, `--ink #0a0e12` ground, one phosphor accent):
- **Primary — a top/bottom edge fade (mask-image).** Cards dissolve into the console's dark ground at the bounded edges; the soft cutoff *is* the "more below / more above" signal, with zero added chrome. Top fade appears only once scrolled; bottom fade while more remains. This is the most native gesture for a dark-ground telemetry console — content fading into the dark, not a UI widget pasted on.
- **Secondary — a deliberately VISIBLE thin scrollbar,** tinted with `--fg-faint`/`--line` on a transparent track. This is the ONE place on the board we intentionally break the hidden-scrollbar convention that `.ak-strip` uses (`scrollbar-width:none`, globals.css:447-452). Rationale: the horizontal strip earns a hidden scrollbar because snap-scroll + a peeking next column already imply scrollability; a **vertical wall of full-width cards offers no peek**, so an honest thin rail is the discoverability fix — and discoverability is the exact complaint. The summary's existing `Bookkeeping 133 · Parked 20 · Deferred 0` count reinforces it (you can see there are 153 items; the panel shows ~8) — no separate "scroll for more" label needed.

## 3. Mobile touch behavior + horizontal-overflow invariant
Mirror `.ak-drawer__body`'s proven mobile wiring: **`overscroll-behavior: contain`** (momentum stays inside the drawer; does not chain-scroll the page behind once you hit an end) and **`-webkit-overflow-scrolling: touch`** (iOS momentum). The shelf is full-width BELOW `.ak-strip`, not nested in it, so vertical drawer scroll and the board's horizontal strip scroll live on different axes/elements and don't steal each other.
**Regression guard (must not reintroduce horizontal overflow):** html AND body both pin `overflow-x: hidden` (globals.css:105, 117 — the document-ROOT containment invariant). Setting `overflow-y:auto` on the body implicitly computes `overflow-x` to `auto` too (CSS spec), which would let a pathological card surface a horizontal scrollbar INSIDE the drawer. So the body must **explicitly pin `overflow-x: hidden` (or `clip`)** alongside `overflow-y:auto`. Cards are already `width:100%` (`.ak-cardbtn`), so this only hardens against a future wide child.
**Measure-don't-assume note for the executor:** do NOT copy `.ak-drawer__body`'s `flex:1 1 auto` + `min-height:0` — those exist because that body is a flex CHILD of a fixed column that must shrink below content. `.ak-shelf__body` is itself the scroll container with an explicit `max-height`, so it scrolls directly; the min-height:0 trick is unnecessary here and would only confuse.

## 4. Grouping at 133 items — sticky labels: CALL IT IN
Make `.ak-shelf__group-label` **`position: sticky; top: 0`** within the scroll container. Reason: the Bookkeeping group alone is 133 cards — its label scrolls out of view on the first flick and never returns, so without sticky you lose all "which section am I in?" context. A pinned thin uppercase mono label reads exactly like a console section header — dead on-aesthetic, one property, real payoff at this item count. Caveat the executor must honor: the sticky label needs an **opaque `--panel` background** (+ a hairline `--line` bottom border) so scrolling cards don't ghost through it; otherwise transparent text over moving cards looks broken.

---
**design POV:** Make the opened shelf body its OWN bounded scroll panel — `max-height` in `dvh` at roughly half-to-two-thirds of the visual viewport, `overflow-y:auto` with `overflow-x:hidden` pinned, `overscroll-behavior:contain` + `-webkit-overflow-scrolling:touch` mirroring `.ak-drawer__body` — signalled by a dark-ground edge fade plus a deliberately-visible thin scrollbar (the one justified break from the board's hidden-scrollbar convention), with sticky per-kind group labels so context survives a 133-card scroll.
